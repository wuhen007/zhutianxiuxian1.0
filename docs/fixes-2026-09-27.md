# 修仙配置、轮回大道与秘境动作修复

## 配置保存保护

- 主配置改为临时文件写入、刷盘、原子替换，文件占用时有限重试。
- 替换失败不退回原地覆盖，避免磁盘写满后配置被清空。
- 主配置为空、结构残缺或缺少秘境参数/任务 cron 时明确报错，不把空对象当作有效配置继续初始化。
- 保存前保留固定一份 `.last-good` 健康配置；不自动应用备份或覆盖玩家存档。

如果启动时明确提示配置不完整，应核对并恢复自己的健康备份，而不是用他人配置或仓库示例覆盖本机运营配置。

## 轮回大道升级

- 修复阶段升级后名称和能力不同步、岁月境错误沿用生死境进度的问题。
- 跨阶段保留溢出进度，批量逐次按当前阶段计算费用。
- 岁月境大圆满100%封顶，未执行的批量次数不收费；资源不足整批不扣费。
- 保留原有准帝/等效权柄门槛、资源成本和进度表。
- 同玩家修炼持锁后读取/保存，避免并发覆盖扣费或进度。
- 旧字段规范化不依据历史记录猜测补发等级；查询只读，显式同步不扣资源。

```text
#轮回大道
#同步轮回大道
#修炼轮回大道
#修炼轮回大道*10
```

修炼次数支持1～99。旧记录只保留最近500条，未知扩展字段保留。

## 大圆满玩家的时代技能

- 达到**岁月境大圆满阶段**即可使用 `#推进时代 1000`；无需机器人主人身份，也不要求阶段进度100%。
- 单次1～10000整数年；没有新增资源扣费或任意冷却。
- 使用专用玩家入口，排队后复核角色境界、世界开关与当前年份；不伪造 `e.isMaster`，不调用管理员命令入口。
- 本时代管理器的玩家推进、后台推进和管理员时代修改共用进程内队列。
- `#设置时代`、`#下一千年`、`#下一个时代`、`#掌控生死` 仍保留原有管理员限制。

时代推进会影响全服并沿用既有时代过渡副作用；测试没有在真实世界执行推进。

## 秘境已结算但造化仍被拦截

- 普通秘境结算后可能保留完成态动作键。造化入口不再仅凭键存在就判定繁忙。
- 只放行明确已结束的标准真身秘境动作：关闭标记完整、结束时间有效且已过去；如有批量计数还需全部结算。
- 活动标记为0、未知/损坏记录、法身行动和其他玩法不会因为过期就被跳过。
- 造化与秘境结算共用既有玩家锁/Redis锁；奖励持久化尚在进行时等待或提示稍后重试。
- 不清空行动历史，不重发秘境奖励，不动独立法身任务；原造化物品、时长和成本保持不变。

## 验证方式

在项目依赖可解析的环境中运行：

```shell
node --test test/config-file-safety.test.mjs test/reincarnation-way.test.mjs test/reincarnation-era-access.test.mjs test/creation-action-gate.test.mjs
```

这些测试使用内存模拟的玩家文件、Redis、消息发送及世界副作用，不依赖生产账号或群号。配置集成测试使用项目的 `yaml` 依赖；如缺少依赖会明确标记跳过。

可选环境变量：

- `CONFIG_FIX_TEST_TMP`：配置文件测试的临时目录。
- `CONFIG_FIX_YAML_MODULE`：指定 YAML 包入口。
- `CONFIG_FIX_SNAPSHOT`：指定健康配置副本；默认验证仓库提供的配置结构。
- `REINCARNATION_HOST_PLUGIN` / `CREATION_HOST_PLUGIN`：指定测试依赖的插件根目录；默认当前仓库。
- `REINCARNATION_ORIGINAL_DAOFA` / `REINCARNATION_ACCESS_BEFORE_DAOFA` / `CREATION_ORIGINAL_SOURCE`：可选的变更前源码副本，用于对照复现旧错误；不指定时仅跳过相应源码对照用例。

## 升级与范围

更新代码后需重启喵崽加载。升级不批量迁移角色、不重放结算、不回滚资源；首次正常修炼或显式同步才按新规则保存轮回字段。

本次只包含相关修仙代码、测试与说明。玩家数据、运营配置、恢复备份、诊断日志，以及独立QQBot/店铺插件不随此提交上传。

锁保护针对现有单进程玩法调度；不宣称跨多个机器人进程的全服事务。旧多文件奖励流程若进程中断仍需依据日志逐项核对，禁止因看到残留动作就直接重发奖励。
