# 道具发单与领取（公益版）

面向公益运营的道具发放通道：**群主只能"发单"，玩家本人"领取"才真正到账。**
这样每一件道具都有"谁发的、谁领的、隔了多久"的记录，收钱发单、代领都会留痕；领取时会固定弹一次公益防诈提示。

相关文件：

| 文件 | 作用 |
|---|---|
| `apps/User/ItemGrant.js` | 指令与文案 |
| `model/itemGrantStore.js` | 发单账本（待领单、额度、熔断、哈希链），纯逻辑可单测 |
| `model/itemGrant.js` | 接游戏存档：查道具定义、入纳戒、上锁 |
| `test/item-grant.test.js` | 账本自测，`node --test test/item-grant.test.js` |

## 一、群主：怎么发单

### 1. 基本格式

```
#派单 @某人 道具名 理由
#派单 @某人 道具名 x2 理由
```

示例：

```
#派单 @张三 返命丹 卡在筑基七天，突破材料不够
#派单 @李四 洗髓丹 x2 刚入群的新人，帮一把
```

- **必须在群里发**，私聊会被拒绝（要让玩家能核对是谁发的）。
- **必须 @ 人**，光写 QQ 号不行。
- 道具名要跟游戏里完全一致（走 `foundthing` 校验），写错会提示"没有这个道具"。
- 数量可选，写 `x2` / `×2` / `*2` 都行，**单次最多 3 件**。
- 理由**必填**，会显示给玩家，也是将来查卖单的依据；不写则为"未填写"。
- 道具按它自己的类目入纳戒（丹药/材料/草药/装备…），不用你指定。

### 2. 发单后会发生什么

```
群主 #派单  →  生成待领单（7 天有效，占用 1 次周额度）
            →  群里回一条带 @ 的提示
            →  玩家自己 #领取 时，才真正进纳戒
```

群里的提示长这样：

```
@张三 群主给你发了：返命丹 ×1（N-1A2B3C）
理由：卡在筑基七天
请本人私聊我发「#领取」到账，7 天内有效。
本服公益免费，收费即骗子——道具本来就该免费给你。
```

**注意：这时候东西还没到玩家背包里。** 不要对玩家说"已经发了"，说"给你发了一张单，回 `#领取` 就到账"。

### 3. 额度与限制

| 项目 | 默认 | 说明 |
|---|---|---|
| 每周发单数 | 10 单/人 | 按发单人算，周一 04:00 重置；撤销会退回 |
| 单次件数 | 1–3 件 | 超过 3 按 3 算 |
| 单人同道具 | 同时只能 1 张待领单 | 防止一次堆一堆 |
| 单子有效期 | 7 天 | 过期作废，额度退回 |
| 全服日池 | 单道具 30 件/天 | 熔断，防批量刷 |

额度不够会直接告诉你 `本周发单额度已用完（10/10）`。

### 4. 发错了怎么办

```
#撤单 N-1A2B3C
```

- 只能在**玩家还没领**的时候撤，撤完额度立刻退回。
- 玩家已经领了就不能撤 —— 这时只能走管理员回收流程，群主没有回收权（防止"不听话就收回"式的反向要挟）。

## 二、玩家：怎么领取

### 1. 三步

1. 群里看到群主 @ 你，记下单号（`N-XXXXXX`）。
2. **私聊机器人**（群里发不管用，会提示你转私聊）发：

```
#领取
```

3. 到账，收到流水号：

```
【已到账】返命丹 ×1（流水 0001-8F3A，已锁定自用）
```

紧接着是防诈提示（**每个号只在第一次领取时弹完整版**，之后是一行简版）：

```
本服公益运营，全程免费。机器人不会向你收费，也不会索要账号或验证码。
凡以「代领/包过/内部渠道/出售道具」收费的，都是骗子。
遇收费请截图发我，不必先付款。
```

### 2. 领取的几个要点

- **必须私聊**：群里发 `#领取` 只会回你一句"私聊我"，不会发货。群里不刷流水，也不给别人看。
- **只能本人领**：单子绑的是你的 QQ，别人拿到单号也领不了。
- **一次领完**：发一次 `#领取`，会把你所有待领单一起结掉，不用一张张点。
- **不用记单号**：`#领取` 直接找你自己名下的待领单。
- **忘了有哪些**：发 `#我的单`，列出待领的道具、单号、来自哪个群。
- **到账即锁定**：发出去的道具 `islockd = 1`，**不能出售、不能交换、不能转移**，只能自己用。这是"只能自用"的技术落点，不是口头规定。

### 3. 领不到时常见原因

| 提示 | 原因 | 怎么办 |
|---|---|---|
| 当前没有待领取的道具 | 群主还没发，或已经领过 | `#我的单` 确认 |
| 对方还没有修仙存档 | 目标玩家没玩过（发单时就拦了） | 让玩家先发一次修仙指令 |
| 今日该道具全服发放已达上限 | 触发日池熔断 | 次日再领，或找管理员 |
| 发放失败：… | 入纳戒异常 | 把提示发给管理员，单子还在，可重试 |
| 单子过期 | 超过 7 天没领 | 让群主重新发一张 |

## 三、举报与防诈

```
#举报 张三收我 20 元才肯给道具
```

生成工单号（`A-XXXX`），48 小时内处理。文案会明确告诉玩家"请勿付款"。

**为什么这套能压住卖单**：群主收钱只能发单，玩家还得自己来领、还得有存档，收了钱不一定能兑现；而领取页和发单提示都写着"道具本来就该免费给你"——买家知道不该付钱，这门生意就没了需求端。

## 四、数据与对账

账本文件：`resources/data/item_grant.json`

```jsonc
{
  "orders": {
    "N-1A2B3C": {
      "id": "N-1A2B3C",
      "groupId": "123456",
      "grantedBy": "群主QQ",        // 谁发的
      "role": "owner",
      "targetQQ": "玩家QQ",          // 发给谁
      "itemName": "返命丹",
      "itemClass": "丹药",
      "qty": 1,
      "reason": "卡在筑基七天",
      "status": "pending|claimed|expired|revoked",
      "createdAt": 1763600000,
      "expireAt": 1764204800,
      "claimedAt": 1763600900,       // 谁领的、什么时候
      "latency": 900,                // 发单到领取隔了多少秒
      "revokedBy": ""
    }
  },
  "events": [                        // 只增不改，带哈希链
    { "seq": 1, "ts": 1763600900, "orderId": "N-1A2B3C", "itemName": "返命丹",
      "qty": 1, "mint": "0001-8F3A", "actor": "player",
      "grantedBy": "群主QQ", "claimedBy": "玩家QQ", "groupId": "123456",
      "action": "grant", "prevHash": "GENESIS", "hash": "…" }
  ],
  "reports": [ { "id": "A-1234", "qq": "举报人", "text": "…", "ts": 0, "status": "open" } ],
  "tips": { "玩家QQ": 1 }            // 是否已弹过完整防诈提示
}
```

对账三招：

- **按人**：搜 `claimedBy`，看某玩家领过什么、谁发的。
- **按群主**：搜 `grantedBy` + 看 `latency`。正常单子是玩家过一阵才领（几分钟到几天）；**秒领**说明是同一人在操作两台设备，可疑。
- **按链**：`events` 每条 `hash = sha256(prevHash + 本条内容)`，改任何一条都会断链，用 `GrantStore.verifyChain()` 可验。

## 六、老指令已停用

这几个老入口**不再发放道具**，只会回一份派单说明：

| 老指令 | 原行为 | 现在 |
|---|---|---|
| `#发道具名*数量@人` | 直接进纳戒 | 拦下，回操作说明 |
| `#全体发...` | 给全群每人发 | 拦下，回操作说明 |
| `#发拉新奖励1@人` | 按档位直发 | 拦下，回操作说明 |

原因很简单：这些入口是直发，**不生成待领单、不上锁、不进账本**，玩家拿到就能 `#赠送` 转手，等于把整套治理绕过去了。

提示只回给**原本有权限的人**（主人 / 修仙管理员 / 群主），普通玩家发这些指令仍然静默，和改造前一样，不会被打扰。

## 七、已知边界

- **私聊推送没做**：发单提示只发在群里（@ 玩家）。玩家没看到可以私聊我发 `#我的单` 自查。要做私聊主动推送得按适配器拼 session，跨平台不稳，先不做。
- **领取依赖私聊可达**：机器人得能收到玩家私聊（好友或临时会话）。收不到私聊的号，玩家就领不到，需要加好友或换适配器放行。
- **锁定拦得住出售/交换**：`islockd == 1` 会被 `equipmentSale` 和通用出售链路过滤。如果还有别的玩家间转移入口没走这个判断，需要在那边补一行。
- **代练管不了**：道具不能交易了，但"帮你练到能领的境界"属于服务，技术拦不住，只能靠关键词提示。
- **群主身份依赖适配器**：用的是 `e.member?.is_owner / is_admin`，适配器没给这个字段时会退化成"只有主人能发单"。
